## 1. What is a Layout File (`_layout.jsx`)?

In Expo Router, any file named `_layout.jsx` (or `_layout.tsx`) acts as a **wrapper** for all sibling route files and nested folders in that directory:

- **Persistent Context**: Code in `_layout.jsx` does not unmount when navigating between child screens.
- **Navigator Container**: It is where you define how routes transition (e.g., `<Stack />`, `<Tabs />`, `<Drawer />`, or `<Slot />`).
- **Global UI Elements**: Providers (Theme, Auth, Redux) and global wrappers (like Safe Area Providers) belong in the root layout.

```text
app/
├── _layout.jsx   <-- Wraps all routes below with Stack navigation & global styles
├── index.jsx     <-- Route: "/"
├── about.jsx     <-- Route: "/about"
└── contact.jsx   <-- Route: "/contact"
```

## 2. `<Slot />` vs `<Stack />`

| Feature | `<Slot />` | `<Stack />` |
| :--- | :--- | :--- |
| **What it is** | A simple view outlet (like `<Outlet />` in React Router / React Web). | A native mobile stack navigator (built on React Navigation & `react-native-screens`). |
| **Header Bar** | No native header bar rendered. | Automatically renders native header with title and back navigation. |
| **Transitions** | Instant screen replacement (no native slide/push animations). | Native OS push/pop screen transitions (slide on Android, swipe on iOS). |
| **Gestures** | No swipe gestures. | Supports native swipe-to-back gesture on iOS. |
| **Best For** | Custom custom headers, simple tab wrappers, or bare layout templates. | Standard multi-screen mobile apps with hierarchical navigation. |

### Example: Switching from `<Slot />` to `<Stack />`
```jsx
// 1. With Slot (No header, just renders the active screen):
export default function Layout() {
  return <Slot />;
}

// 2. With Stack (Provides native headers, back buttons, and slide transitions):
export default function Layout() {
  return <Stack />;
}
```

## 3. The `<Stack />` Navigator in Depth

[`<Stack />`](file:///c:/Users/tahmi/OneDrive/Desktop/shelfie_app/app/_layout.jsx#L8) renders a native stack. Each new screen visited is pushed onto the stack; going back pops the top screen off.

### Global vs Per-Screen Options
You can configure header styles in two ways:
1. **`screenOptions` on `<Stack>`**: Applies defaults globally to **all** screens in that stack.
2. **`options` on `<Stack.Screen>`**: Customizes or overrides settings for **that specific screen**.

```jsx
<Stack
  screenOptions={{
    headerStyle: { backgroundColor: '#0284c7' }, // Global background
    headerTintColor: '#ffffff',                  // Global text & icon color
    headerTitleStyle: { fontWeight: 'bold' },    // Global title typography
  }}
>
  {/* Specific screen configurations */}
  <Stack.Screen name="index" options={{ title: 'Home' }} />
  <Stack.Screen name="about" options={{ title: 'About Us' }} />
  <Stack.Screen name="contact" options={{ headerShown: false }} /> {/* Hides header */}
</Stack>
```

## 4. Customizing Screen Headers

### Essential Header Properties

| Property | Type | Description |
| :--- | :--- | :--- |
| `title` | `string` | The text shown in the center/left of the header bar. |
| `headerShown` | `boolean` | Set `false` to completely hide the top navigation bar. |
| `headerStyle` | `object` | Styles the header container (e.g. `backgroundColor`, `elevation`, `shadowOpacity`). |
| `headerTintColor` | `string` | Hex/RGB color for the title, back chevron, and header buttons. |
| `headerTitleStyle` | `object` | Font styling for the title (`fontSize`, `fontWeight`, `fontFamily`). |
| `headerTitleAlign` | `'left' \| 'center'` | Centered title on Android/Web (`'center'` is already default on iOS). |
| `headerBackTitle` | `string` | Custom label next to the back arrow on iOS (e.g. `"Back"`). |
| `headerBackVisible`| `boolean` | Explicitly show/hide the back button (`true` or `false`). |
| `headerRight` | `() => ReactNode` | Renders a custom component (e.g. settings icon or cart button) on the right side. |
| `headerLeft` | `() => ReactNode` | Renders a custom component on the left side (replaces default back arrow). |

## 5. The Back Button: Why It Appears or Disappears

> ### 🔍 Why `<Stack />` Was Not Showing a Back Button by Default:

In native mobile navigation and Expo Router, a back button **only appears under specific conditions**:

### 1. Root Screen Has No Previous History (`canGoBack === false`)
On the Home screen (`app/index.jsx`), there is no previous screen in the stack. By design, the initial screen never has a back button because there is nowhere to go back to.

### 2. Direct URL Loading or Page Refresh on the Web
If you test in a web browser (`npm run web` / `http://localhost:8081/about`) or refresh the browser page while on `/about`:
- The browser loads `/about` as the **first and only** route in the React Navigation state.
- Because there is no preceding screen in the app memory (`history length = 1`), `canGoBack()` returns `false`, and React Navigation omits the back button.
- **Solution**: Navigate from Home (`/`) to `/about` by clicking your `<Link href="/about">` without refreshing the browser. The stack will have `[Home, About]`, and the back button will appear!

### 3. Replaced History (`replace` instead of `push`)
If navigation occurred via `router.replace('/about')` or `<Link href="/about" replace>`, the current screen is *swapped* rather than added on top. The previous screen is removed, eliminating the back button.

### 4. How to Force or Customize a Back Button
If you want a back button even when testing or want a custom look, you can define `headerLeft` or `headerBackVisible`:

```jsx
import { router } from 'expo-router';
import { Pressable, Text } from 'react-native';

<Stack.Screen
  name="about"
  options={{
    title: 'About',
    // Custom back action
    headerLeft: () => (
      <Pressable onPress={() => router.back()} style={{ paddingRight: 10 }}>
        <Text style={{ color: '#333', fontSize: 16 }}>‹ Back</Text>
      </Pressable>
    ),
  }}
/>
```

## 7. Advanced Real-World Stack Patterns

### A. Modal Screens (Bottom Sheet Presentation)
For popups, login dialogs, or filter sheets that slide up from the bottom:

```jsx
<Stack.Screen
  name="login-modal"
  options={{
    presentation: 'modal', // 'modal' | 'transparentModal' | 'card'
    title: 'Sign In',
  }}
/>
```

### B. Dynamic Header Title from Screen Content
Instead of static titles in `_layout.jsx`, you can set the title from inside any screen file using `<Stack.Screen />` from within that file:

```jsx
// Inside app/product/[id].jsx
import { Stack, useLocalSearchParams } from 'expo-router';

export default function ProductDetail() {
  const { id } = useLocalSearchParams();

  return (
    <>
      <Stack.Screen options={{ title: `Product #${id}` }} />
      {/* Component content */}
    </>
  );
}
```

## 8. Common Pitfalls & Gotchas

| Pitfall | Cause | Solution |
| :--- | :--- | :--- |
| **`Stack.Screen name` typo** | Setting `name="About"` when the file is `about.jsx`. | The `name` prop MUST match the exact filename without the `.jsx` / `.tsx` extension. |
| **No back button on reload** | Testing on Web and pressing F5 on `/about`. | Reload on the home screen (`/`) and click the link to populate the stack history. |
| **Overlapping headers** | Having a root `<Stack>` AND an inner `<Stack>` without setting `headerShown: false` on the parent. | Hide the outer stack header for nested stacks (`options={{ headerShown: false }}`). |
| **Wrapping `<Stack>` inside fixed views** | Placing non-flex `<View>` or text elements directly as siblings to `<Stack>` can break screen layouts. | If you need custom floating footers or modals, position them absolutely or render them inside screen components. |
