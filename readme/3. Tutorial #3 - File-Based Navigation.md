## 1. Core Concept: File-System Routing

In traditional React Native apps (using bare React Navigation), you had to manually register every screen inside a navigator tree (`<Stack.Navigator>` with `<Stack.Screen name="About" component={About} />`).

With **Expo Router**, routing is driven directly by the file structure in the `app/` folder:
- **Zero boilerplate registration**: Create a file in `app/`, and it immediately becomes a routable screen.
- **Native performance**: Under the hood, screens compile into native navigation transitions on iOS and Android.
- **Automatic deep linking & web URLs**: Paths work identically whether the app is running on iOS, Android, or the Web.

## 3. The `<Link>` Component in Depth

The [`Link`](file:///c:/Users/tahmi/OneDrive/Desktop/shelfie_app/app/index.jsx#L2) component is imported from `expo-router`. It renders an accessible, touchable element that pushes or replaces routes on the navigation stack.

```jsx
import { Link } from 'expo-router';
```

### Essential Props

| Prop | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `href` | `string` \| `object` | *required* | The target path (e.g., `"/"`, `"/about"`, `"/contact"`). |
| `replace` | `boolean` | `false` | If `true`, replaces the current route instead of pushing a new screen onto the stack (user cannot go back to the previous screen). |
| `asChild` | `boolean` | `false` | Forwards navigation and touch behavior to a custom child component (e.g. `<Pressable>` or custom button). |
| `style` | `StyleProp` | `undefined` | Styles applied to the text element rendered by `Link`. |

### Example Usages

#### 1. Basic Text Link
```jsx
<Link href="/about" style={styles.link}>
  Go to About
</Link>
```

#### 2. Replacing History (Useful for Login / Onboarding)
```jsx
<Link href="/dashboard" replace style={styles.link}>
  Continue to Dashboard
</Link>
```

## 4. Wrapping Custom Buttons with `asChild`

By default, `<Link>` renders text. In production apps, navigation triggers are usually custom styled buttons, cards, or touchable areas.

When wrapping a `<Pressable>` or `<TouchableOpacity>`, you **must** pass `asChild`:

```jsx
import { Link } from 'expo-router';
import { Pressable, Text, StyleSheet } from 'react-native';

export default function ButtonLinkExample() {
  return (
    <Link href="/about" asChild>
      <Pressable style={styles.button}>
        <Text style={styles.buttonText}>Learn More</Text>
      </Pressable>
    </Link>
  );
}

const styles = StyleSheet.create({
  button: {
    backgroundColor: '#0284c7',
    paddingVertical: 12,
    paddingHorizontal: 24,
    borderRadius: 8,
    alignItems: 'center',
  },
  buttonText: {
    color: '#ffffff',
    fontWeight: 'bold',
    fontSize: 16,
  },
});
```

> **Why `asChild`?**  
> `asChild` clones the child element and merges the navigation touch handlers onto it, preventing nested touch conflict warnings.

## 5. Declarative vs Programmatic Navigation

In real-world projects, you will use both patterns depending on the context:

### A. Declarative (`<Link />`)
Use for standard clickable UI elements, menus, footer links, and breadcrumbs:

```jsx
<Link href="/about">About Us</Link>
```

### B. Programmatic (`router`)
Use inside event handlers, form submissions, timer callbacks, or after asynchronous API requests:

```jsx
import { router } from 'expo-router';
import { Button } from 'react-native';

const handleFormSubmit = async () => {
  await submitContactForm();
  
  // Navigate to confirmation page
  router.push('/about');

  // Or replace current page:
  // router.replace('/home');

  // Or go back one step:
  // router.back();
};
```

## 7. Common Pitfalls & Real-World Gotchas

| Pitfall | Problem | Fix |
| :--- | :--- | :--- |
| **Missing leading slash in `href`** | Writing `href="about"` instead of `href="/about"` can cause relative path resolution errors. | Always use absolute root paths for top-level routes (e.g. `href="/about"`). |
| **Casing typo in styles (e.g. `borderbottomWidth`)** | React Native styles are strict camelCase JavaScript objects. `borderbottomWidth` is silently ignored or throws a warning. | Use `borderBottomWidth: 1`. |
| **Nesting touchables without `asChild`** | `<Link href="/about"><Pressable>...</Pressable></Link>` without `asChild` creates two competing touch listeners. | Always add `asChild` to `<Link>` when wrapping a touchable component. |
| **File named with uppercase or spaces** | Naming files like `About Page.jsx` creates problematic URL paths. | Use lowercase, hyphenated file names (e.g., `about-page.jsx`, `contact.jsx`). |
| **Stale cache after adding new route files** | Metro bundler may occasionally fail to discover newly added files in `app/`. | Restart Metro with clean cache: `npx expo start -c`. |

## 8. Quick Reference Cheat Sheet

### Common Route Conventions
```text
app/index.jsx           -> /
app/about.jsx           -> /about
app/contact.jsx         -> /contact
app/settings/index.jsx  -> /settings
app/settings/account.jsx-> /settings/account
```

### Essential Navigation Snippets
```jsx
// 1. Declarative Link
<Link href="/about">About</Link>

// 2. Button Link with asChild
<Link href="/about" asChild>
  <Pressable style={styles.btn}><Text>About</Text></Pressable>
</Link>

// 3. Programmatic Push
router.push('/contact');

// 4. Programmatic Replace
router.replace('/');

// 5. Go Back
router.back();
```
