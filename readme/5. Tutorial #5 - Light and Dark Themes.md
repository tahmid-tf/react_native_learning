## 1. Theming Architecture & Color Token Design

Hardcoding hex codes (like `#fff` or `#000`) across components makes apps difficult to maintain and impossible to re-theme.

In production apps, centralized design tokens are stored in a constants file such as [constants/colors.jsx](file:///c:/Users/tahmi/OneDrive/Desktop/shelfie_app/constants/colors.jsx):

```jsx
export const Colors = {
  // Brand colors (shared across both themes)
  primary: "#6849a7",
  warning: "#cc475a",

  // Dark Theme Tokens
  dark: {
    text: "#d4d4d4",
    title: "#fff",
    background: "#252231",
    navBackground: "#201e2b",
    iconColor: "#9591a5",
    iconColorFocused: "#fff",
    uiBackground: "#2f2b3d",
  },

  // Light Theme Tokens
  light: {
    text: "#625f72",
    title: "#201e2b",
    background: "#e0dfe8",
    navBackground: "#e8e7ef",
    iconColor: "#686477",
    iconColorFocused: "#201e2b",
    uiBackground: "#d6d5e1",
  },
};
```

### Best Practice: Semantic Token Names
Notice the naming convention:
- **Good (Semantic)**: `background`, `title`, `navBackground`, `uiBackground`, `text`.
- **Bad (Literal colors)**: `white`, `darkGray`, `lightBlue` (a color named `white` might need to be dark gray in dark mode, causing confusion).

## 2. Detecting the Device Theme (`useColorScheme`)

React Native provides the [`useColorScheme`](file:///c:/Users/tahmi/OneDrive/Desktop/shelfie_app/app/_layout.jsx#L1) hook to detect the user's preferred OS appearance (Light or Dark).

```jsx
import { useColorScheme } from 'react-native';
import { Colors } from '../constants/colors';

const colorScheme = useColorScheme(); // returns 'light' | 'dark' | null | undefined
```

### The Null-Coalescing Fallback Pattern
`colorScheme` can occasionally be `null` or `undefined` (e.g. during app startup or on web before hydration). Always provide a fallback:

```jsx
const theme = Colors[colorScheme] ?? Colors.light;
```

If `colorScheme` is `'dark'`, `theme` resolves to `Colors.dark`. Otherwise, it safely defaults to `Colors.light`.

## 3. Configuring `app.json` for Dark Mode Support

In [app.json](file:///c:/Users/tahmi/OneDrive/Desktop/shelfie_app/app.json), the key `"userInterfaceStyle"` controls whether Expo allows dynamic theming:

```json
{
  "expo": {
    "userInterfaceStyle": "automatic"
  }
}
```

| Option | Behavior |
| :--- | :--- |
| `"automatic"` | **Recommended for production.** Allows the app to dynamically switch between light and dark when the user toggles device settings. |
| `"light"` | Locks the app permanently to light mode. `useColorScheme()` will always return `'light'` on native devices. |
| `"dark"` | Locks the app permanently to dark mode. |

> **Gotcha:** If your dark theme does not work when changing device settings on physical phones or simulators, verify that `"userInterfaceStyle"` is set to `"automatic"` in `app.json`.

## 4. Applying Themes to Layouts & Navigation (`app/_layout.jsx`)

By reading the theme in the root layout, your top header bar and global navigation automatically update to match the active theme:

```jsx
import { useColorScheme } from "react-native";
import { Stack } from "expo-router";
import { StatusBar } from "expo-status-bar";
import { Colors } from "../constants/colors";

const RootLayout = () => {
  const colorScheme = useColorScheme();
  const theme = Colors[colorScheme] ?? Colors.light;

  return (
    <>
      {/* 1. Dynamic Status Bar Icons */}
      <StatusBar style={colorScheme === 'dark' ? 'light' : 'dark'} />

      {/* 2. Dynamic Stack Header */}
      <Stack
        screenOptions={{
          headerStyle: {
            backgroundColor: theme.navBackground, // Theme background
          },
          headerTintColor: theme.title,           // Theme text & icons
          headerTitleStyle: {
            fontWeight: "bold",
          },
        }}
      >
        <Stack.Screen name="index" options={{ title: "Home" }} />
        <Stack.Screen name="about" options={{ title: "About" }} />
        <Stack.Screen name="contact" options={{ title: "Contact" }} />
      </Stack>
    </>
  );
};

export default RootLayout;
```

## 5. The Status Bar Component (`expo-status-bar`)

The status bar displays device time, battery, and Wi-Fi indicators at the very top of the screen:

```jsx
import { StatusBar } from "expo-status-bar";
```

### Style Options:
- `style="light"`: Forces status bar text and icons to be white (use on dark backgrounds).
- `style="dark"`: Forces status bar text and icons to be black/dark (use on light backgrounds).
- `style="auto"`: Automatically picks icon color based on system appearance.

```jsx
// Best practice for dynamic themes:
<StatusBar style={colorScheme === 'dark' ? 'light' : 'dark'} />
```

## 6. Applying Themes to Individual Screens (`app/about.jsx`)

To apply theme colors to screen containers, headings, and cards, read `useColorScheme` in the screen component and merge the dynamic styles:

```jsx
import { StyleSheet, Text, View, useColorScheme } from "react-native";
import { Link } from "expo-router";
import { Colors } from "../constants/colors";

const About = () => {
  const colorScheme = useColorScheme();
  const theme = Colors[colorScheme] ?? Colors.light;

  return (
    // Style array merging: base styles + dynamic theme background
    <View style={[styles.container, { backgroundColor: theme.background }]}>
      <Text style={[styles.title, { color: theme.title }]}>About Page</Text>
      
      <Link href="/" style={[styles.link, { color: theme.text, borderColor: theme.text }]}>
        Back Home
      </Link>
    </View>
  );
};

export default About;

const styles = StyleSheet.create({
  container: {
    flex: 1,
    alignItems: "center",
    justifyContent: "center",
  },
  title: {
    fontSize: 18,
    fontWeight: "bold",
  },
  link: {
    marginVertical: 10,
    borderBottomWidth: 1,
  },
});
```

## 7. Production Pattern: Custom `useTheme` Hook

Instead of repeating `const colorScheme = useColorScheme(); const theme = Colors[colorScheme] ?? Colors.light;` in every screen, create a reusable hook in `hooks/useTheme.js`:

```javascript
// hooks/useTheme.js
import { useColorScheme } from 'react-native';
import { Colors } from '../constants/colors';

export function useTheme() {
  const colorScheme = useColorScheme();
  const isDark = colorScheme === 'dark';
  const theme = Colors[colorScheme] ?? Colors.light;

  return {
    theme,
    isDark,
    colorScheme,
  };
}
```

### Using It Anywhere in Your App:
```jsx
import { useTheme } from '../hooks/useTheme';

export default function MyScreen() {
  const { theme, isDark } = useTheme();

  return (
    <View style={{ backgroundColor: theme.background }}>
      <Text style={{ color: theme.text }}>
        {isDark ? 'Dark Mode Active' : 'Light Mode Active'}
      </Text>
    </View>
  );
}
```

## 8. Common Pitfalls & Gotchas

| Issue | Cause | Solution |
| :--- | :--- | :--- |
| **Dark mode never turns on on native device** | `"userInterfaceStyle": "light"` in `app.json`. | Set `"userInterfaceStyle": "automatic"` in `app.json`. |
| **App crashes: `Cannot read properties of undefined`** | Accessing `Colors[colorScheme].background` when `colorScheme` is null/undefined. | Always use nullish coalescing: `Colors[colorScheme] ?? Colors.light`. |
| **Invisible status bar icons** | Setting `<StatusBar style="light" />` over a white navigation bar. | Ensure contrast: dark backgrounds get `style="light"`, light backgrounds get `style="dark"`. |
| **Hardcoded colors overriding theme** | Forgetting `backgroundColor: "#fff"` in a component's `StyleSheet`. | Remove hardcoded background/color properties from `StyleSheet` and inject them dynamically via array styles `[styles.container, { backgroundColor: theme.background }]`. |

```jsx
import { useColorScheme } from 'react-native';
```
