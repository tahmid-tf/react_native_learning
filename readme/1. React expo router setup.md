## 1. Overview: What is Expo Router?

**Expo Router** brings file-system based routing to React Native and Expo (similar to Next.js in React web).
- Every file created inside the `app/` (or `src/app/`) directory automatically becomes a route/screen in your app.
- Native navigation animations, deep linking, web URLs, and screen transitions are handled automatically under the hood using `react-native-screens` and React Navigation.

## 2. Method A: Quick Setup (New Project Template)

When starting a new real-world project from scratch, Expo provides starter templates pre-configured with Expo Router:

```bash
# Recommended: Create a new app with Expo Router pre-configured

# Or choose a blank template and customize
npx create-expo-app@latest my-app --template blank
```

## 3. Method B: Manual Setup in an Existing Project

If you created a blank Expo project or need to add Expo Router manually, follow these 5 steps:

### Step 1: Install Required Dependencies
Always install dependencies via `npx expo install` so that compatible versions are resolved for your current Expo SDK:

```bash
npx expo install expo-router react-native-safe-area-context react-native-screens expo-linking expo-constants expo-status-bar
```

### Step 2: Set Entry Point in `package.json`
Open [package.json](file:///c:/Users/tahmi/OneDrive/Desktop/shelfie_app/package.json) and set `"main"` to `"expo-router/entry"`:

```json
{
  "name": "my-app",
  "main": "expo-router/entry",
  "scripts": {
    "start": "expo start",
    "android": "expo start --android",
    "ios": "expo start --ios",
    "web": "expo start --web"
  }
}
```

### Step 3: Configure `app.json`
Open [app.json](file:///c:/Users/tahmi/OneDrive/Desktop/shelfie_app/app.json) and add:
1. `"scheme"`: A unique string identifier for deep linking (e.g. your app slug).
2. `"plugins"`: Add `"expo-router"`.
3. *(Optional)* `"experiments"`: Enable `"typedRoutes": true` if you are using TypeScript.

```json
{
  "expo": {
    "name": "my-app",
    "slug": "my-app",
    "scheme": "myapp",
    "version": "1.0.0",
    "plugins": [
      "expo-router"
    ],
    "experiments": {
      "typedRoutes": true
    }
  }
}
```

### Step 4: Create the Route Directory and Root Screen
1. Create a root folder named `app/` (or `src/app/`).
2. Delete the old root `App.js` or `App.tsx` from the project root if it exists (Expo Router uses `app/index.jsx` instead).
3. Create `app/index.jsx`:

```jsx
import { StyleSheet, Text, View } from 'react-native';

export default function Home() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Welcome to Home Screen!</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: 'center',
    alignItems: 'center',
  },
  title: {
    fontSize: 20,
    fontWeight: 'bold',
  },
});
```

### Step 5: Start the Development Server with Clean Cache
Clear the bundler cache to ensure Metro picks up the new entry point:

```bash
npx expo start -c
```

## 4. Project Structure & File-Based Routing Rules

In Expo Router, the folder structure inside `app/` defines your app navigation hierarchy:

| File Path | Route URL / Path | Description |
| :--- | :--- | :--- |
| `app/index.jsx` | `/` | The initial/home screen |
| `app/about.jsx` | `/about` | Static route: About screen |
| `app/profile/index.jsx` | `/profile` | Nested folder route |
| `app/profile/settings.jsx` | `/profile/settings` | Nested child route |
| `app/product/[id].jsx` | `/product/123` | Dynamic route with param `id` |
| `app/(tabs)/index.jsx` | `/` | Route group (parentheses omitted from URL) |
| `app/+not-found.jsx` | 404 handler | Fallback screen when no route matches |

### Route Groups `(folderName)`
Folders wrapped in parentheses (like `(tabs)` or `(auth)`) are **logical route groups**.
- They do **not** add extra segments to the URL path.
- Useful for grouping routes that share a layout (e.g. tabs navigator or authentication flow) without affecting the URL.

---

## 5. Special Expo Router Files

1. **`_layout.jsx` / `_layout.tsx`**
   - Defines a persistent navigator or wrapper layout for all sibling and child routes.
   - Common layouts: `<Stack />`, `<Tabs />`, `<Drawer />`, or `<Slot />`.

2. **`index.jsx` / `index.tsx`**
   - The default screen for that folder level.

3. **`+not-found.jsx`**
   - Fallback screen for unmatched routes.

4. **`+html.jsx`**
   - Customizes the root HTML template when targeting the Web.

## 6. Navigating Between Screens

Expo Router provides both declarative and programmatic ways to navigate:

### A. Declarative Navigation (`<Link />`)
Use the `Link` component for accessible, touchable navigation elements:

```jsx
import { Link } from 'expo-router';
import { View, Text, StyleSheet } from 'react-native';

export default function HomeScreen() {
  return (
    <View style={styles.container}>
      <Text>Home Screen</Text>
      
      {/* Basic navigation */}
      <Link href="/about" style={styles.link}>
        Go to About Screen
      </Link>

      {/* Wrapping custom components with asChild */}
      <Link href="/profile" asChild>
        <Text style={styles.buttonText}>Open Profile</Text>
      </Link>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center' },
  link: { color: 'blue', marginTop: 10 },
  buttonText: { color: 'purple', fontWeight: 'bold', marginTop: 10 },
});
```

### B. Programmatic Navigation (`router`)
Use `router` for imperative navigation (e.g. after a button press, form submission, or API call):

```jsx
import { router } from 'expo-router';
import { View, Button } from 'react-native';

export default function LoginScreen() {
  const handleLogin = () => {
    // 1. Navigate to a new screen (pushes onto stack)
    router.push('/dashboard');

    // 2. Replace current screen (cannot go back)
    // router.replace('/dashboard');

    // 3. Go back to previous screen
    // router.back();
  };

  return (
    <View>
      <Button title="Login" onPress={handleLogin} />
    </View>
  );
}
```

## 7. Passing Parameters & Dynamic Routes

### Creating a Dynamic Route
File path: `app/users/[id].jsx`

```jsx
import { useLocalSearchParams } from 'expo-router';
import { View, Text, StyleSheet } from 'react-native';

export default function UserDetails() {
  // Access dynamic parameters and query params
  const { id, query } = useLocalSearchParams();

  return (
    <View style={styles.container}>
      <Text style={styles.text}>User ID: {id}</Text>
      <Text style={styles.subtext}>Query: {query}</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center' },
  text: { fontSize: 22, fontWeight: 'bold' },
  subtext: { fontSize: 16, color: 'gray', marginTop: 8 },
});
```

### Navigating with Parameters
```jsx
import { router } from 'expo-router';

// String path with query params:
router.push('/users/42?query=active');

// Object format:
router.push({
  pathname: '/users/[id]',
  params: { id: '42', query: 'active' },
});
```

## 8. Common Layouts: Stack & Tabs

### A. Root Stack Layout (`app/_layout.jsx`)
Wrap routes in a native stack navigator with custom headers:

```jsx
import { Stack } from 'expo-router';

export default function RootLayout() {
  return (
    <Stack
      screenOptions={{
        headerStyle: { backgroundColor: '#f4511e' },
        headerTintColor: '#fff',
        headerTitleStyle: { fontWeight: 'bold' },
      }}
    >
      <Stack.Screen name="index" options={{ title: 'Home' }} />
      <Stack.Screen name="about" options={{ title: 'About Us' }} />
      <Stack.Screen name="users/[id]" options={{ title: 'User Profile' }} />
    </Stack>
  );
}
```

### B. Tabs Layout (`app/(tabs)/_layout.jsx`)
Create bottom tabs using `<Tabs>`:

```jsx
import { Tabs } from 'expo-router';
import { Ionicons } from '@expo/vector-icons';

export default function TabsLayout() {
  return (
    <Tabs screenOptions={{ tabBarActiveTintColor: 'blue' }}>
      <Tabs.Screen
        name="index"
        options={{
          title: 'Home',
          tabBarIcon: ({ color, size }) => (
            <Ionicons name="home" color={color} size={size} />
          ),
        }}
      />
      <Tabs.Screen
        name="explore"
        options={{
          title: 'Explore',
          tabBarIcon: ({ color, size }) => (
            <Ionicons name="search" color={color} size={size} />
          ),
        }}
      />
    </Tabs>
  );
}
```

## 9. Troubleshooting & Gotchas

| Issue | Cause | Solution |
| :--- | :--- | :--- |
| **Blank screen or "Unable to resolve module"** | Metro cache is stale after changing configuration or entry point. | Run `npx expo start -c` to clear cache. |
| **"Unmatched Route" warning** | No file matches the URL path, or typo in `href`. | Verify path spelling or add an `app/+not-found.jsx` file. |
| **Deep links do not work** | Missing `scheme` in `app.json`. | Add `"scheme": "yourapp"` inside `expo` configuration in `app.json`. |
| **Entry point error** | Missing `"main": "expo-router/entry"` in `package.json`. | Check `package.json` and ensure `"main"` points to `"expo-router/entry"`. |
| **Both `App.js` and `app/` exist** | Ambiguous root. Expo Router ignores `App.js`. | Delete or rename the root `App.js` / `App.tsx`. |
